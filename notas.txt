## API Endpoints
- GET /api/rifas - lista pública
- POST /api/rifas - crear (auth, crea ACTIVE + números 1..N)
- GET /api/rifas/[slug] - detalle con números
- POST /api/cart/add - público, crea transaction + reserva números (updateMany)
- POST /api/payments/create - público, crea preferencia MP
- POST /api/webhooks/mercadopago - público, recibe notificaciones MP
- GET /api/auth/me - auth, datos del usuario
- POST /api/auth/login - público
- POST /api/auth/registro - público
- POST /api/auth/verificar - público
- GET /api/dashboard - auth, stats del usuario
- GET /api/payments/[id] - auth, estado del pago

## Frontend
- / - Home con listado de rifas
- /r/[slug] - Detalle de rifa con grilla de números
- /cart?rifa=<slug> - Carrito con selector de números y MP checkout
- /cart/success - Confirmación
- /cart/failure - Error
- /dashboard - Panel del creador

## Prisma Schema (7 models: User, Rifa, Number, Transaction, Affiliate, AffiliateEarning)
- Enums: Plan, RifaStatus, NumStatus, TransStatus, EarnStatus
- Slug único por rifa (title + timestamp)
- Números se crean al crear la rifa (1..totalNumbers, status=AVAILABLE)
- Al comprar: se hace UPDATE de AVAILABLE a RESERVED + transactionId

## Bugs Corregidos
1. Rifa se creaba como DRAFT -> cambiado a ACTIVE
2. Cart/add intentaba crear números nuevos -> cambiado a updateMany
3. Cart/add y payments/create requerían auth -> agregados a bypass del proxy
4. Transaction create sin rifaId en nested create -> separado en dos calls
